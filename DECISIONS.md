# Decisions

- **Agent launcher:** the launcher reads only `state/agent.json`, accepts argv arrays
  rather than shell strings, and saves configuration only through loopback requests.
  It exposes start/stop/status HTTP endpoints and passes the local MCP URL to the
  configured child process.
- **Vault setup:** scaffolding creates only missing root/course files and directories;
  existing vault content is never replaced. Course codes are lowercase safe slugs,
  and course creation is idempotent.

- **Copilot setup:** repository instructions live in `.github/copilot-instructions.md`;
  the manually triggered setup workflow installs Bun and the Python converter
  environment with `uv sync`. `scripts/backup-db.ts` is the canonical backup
  command, while `copy-db.ts` remains available for compatibility.

- **The harness replaces ken.** ken is reference material only: no runtime proxy, no ken process, no reads or writes of `~/.local/share/ken`. The harness owns the vault, MCP surface, mastery and state.
- **Bun install:** installed via the official installer to `~/.bun`; `bun`/`bunx` symlinked into `~/.local/bin` so package scripts work in bash and fish.
- **MCP endpoint:** SDK `WebStandardStreamableHTTPServerTransport` in stateless JSON mode, so it runs natively on Bun without the Node adapter.
- **UI build:** `bun run start` builds the UI only when `dist/ui/index.html` is missing; `HARNESS_SKIP_BUILD=1` and `HARNESS_FORCE_BUILD=1` override this.
- **SQLite:** M0 creates only a `meta` table; the real schema lands in M2/M3.
- **Config:** port 4747, host 127.0.0.1, LAN off by default, all overridable by env (`PORT`, `HOST`, `HARNESS_VAULT`, `HARNESS_DB`, `HARNESS_LAN`, `HARNESS_MCP_TOKEN`).
- **Design register:** product UI, restrained color, dark-first (night study on laptop/phone). One system sans, fixed rem scale, accent reserved for actions/selection/state. Impeccable loaded for token work; Lane C inherits these tokens instead of inventing a palette.
- **ken mapping:** see `docs/ken-mapping.md`. Vault layout follows SPEC (`courses/<code>/`); ken formats are borrowed where useful, but SPEC wins on any conflict.
- **Consolidated SPEC + DESIGN:** `SPEC.md` and `DESIGN.md` come from the student's Downloads; DESIGN wins on look/layout/behavior, SPEC wins everywhere else. Work is tracked as one milestone card at a time.
- **Name:** the app is **Hilum** (`package.json`, title, manifest); icons live in `public/`.
- **Tokens:** CSS `light-dark()` with a `data-theme` override; the active palette is restrained clinical blue (`#315F87` / `#9BC2E3`). Contrast is tested, not eyeballed.
- **Reader prefs:** text size/leading are inline on the article wrapper; markdown must not set its own base font-size or leading.
- **MCP content surface:** `update_course` patches `courses/<code>/course.md` frontmatter (null clears) and is idempotent via `request_id`; notes are resources at `vault://<path>`.
- **Demo data:** screenshots use a fabricated vault under `/tmp/opencode/demo-vault`; never present it as course material, never commit it.
- **Questions live in SQLite.** The vault supplies notes and past papers; `questions` rows are the bank. `source_paper` and `cites` point back into the vault, so nothing is duplicated as markdown.
- **Session brief (WO-6):** `sessions.brief` column holds a short one-line session brief. `set_session_brief` MCP tool sets it; `get_active_session` returns it in the session summary.
- **create_course MCP tool (WO-6):** idempotent, Zod-validated (`code`, `title`, optional `exam_date`). Delegates to `VaultSetupService.createCourse` which scaffolds course directories, writes `course.md` frontmatter, and never overwrites existing content.
- **push_activity (WO-6):** `demo` added to the component catalog description.
- **Agent surfaces (WO-12):** shell status pill shows all five agent states (not connected, starting, working N jobs, idle, failed with reason) and updates from SSE launcher/job events; Agent activity list screen (`/agent`) shows queued/running/finished jobs with type, course, age, Cancel per job and Pause launcher; Settings includes an Agent launcher panel with argv config form (one argument per line), presets for opencode/kilo, working directory, timeout, runs per hour, Test connection (start agent), last run, consecutive failures, and Pause.
- **End-to-end loop test (WO-13):** `tests/loop.test.ts` implements S7 — upload → sort → convert → map_concepts → fake agent completes → plan created → status pill states. Runs as part of `bun test`. A red loop test blocks the merge.
- **Auto-confidence row (WO-5 WP30):** After each graded component (mcq_single, mcq_multi, tf_multi, cloze, matching, ordering, theory, calculation, spot_the_error, short_answer, teach_back, case_vignette, think_aloud, muddy_point, label_diagram, spotter_station, annotated_image) the UI shows a confidence row (Guessing / Fairly sure / Sure) unless the spec already has a `confidence_rating` component. Skipped when the answer is "I don't know" (__idk__). Confidence values are sent with the response as `confidences` per component index. Not stored in the spec.
- **Dictation mic on every textarea (WO-5 WP31):** `useDictation` fixed to use a ref for current value (no stale closure) and accepts a `lang` parameter. Mic button added to Theory, Predict, ShortAnswer, ThinkAloud, MuddyPoint, CaseVignette (per-question), TeachBack, and the Composer message textarea. When browser speech recognition is unavailable, no microphone buttons render. Language stored in `localStorage` under `eh-language`.
- **Language setting (WO-5 WP31):** Settings screen has a "Speech & language" section with a dictation language text input (default: browser language).
- **Practice mode (WO-7 WP35):** New `/practice` screen with concept multi-select. Select concepts, start a session via `session_start` with `concept_ids` stored on `sessions.practice_concepts_json`. `get_active_session` returns `practiceConcepts`. Composer home screen shows "Practice" mode toggle. Practice sessions reference only the selected concepts.
- **Figures registry (WO-10 WP40a):** `figures` table stores registered figures with source, source_id, kind (svg/raster), license, author, attribution_required, caption, and local download path/url. `FiguresService.register()` dedupes by (source, source_id). `list()` returns figures for a course. `download()` fetches from allowlisted hosts only (commons.wikimedia.org, upload.wikimedia.org, pubchem.ncbi.nlm.nih.gov, rcsb hosts), validates content type (image/svg+xml, image/png, image/jpeg, image/webp), caps downloads at 2 MB, and stores locally. SSRF protection: non-allowed hosts and content types are rejected. API: POST /api/figures (register), GET /api/figures?course= (list), GET /api/figures/:id (get), POST /api/figures/:id/download (download), GET /api/figures/:id/file (serve local file). 7 tests in tests/figures.test.ts.
- **Figures search adapter (WO-10 WP40b):** `FigureAdapter` interface with Commons implementation (`CommonsAdapter`). `searchAll()` fans out to enabled adapters and merges results. `resolveAll()` resolves Commons titles/URLs via the MediaWiki API. API: GET /api/figures/search?q= (search), GET /api/figures/sources (enabled sources). MCP tools: `search_figures` (search across sources), `add_figure` (resolve Commons title/URL + register figure). Sources: Commons only (PubChem, RCSB, Servier, OpenStax adapters deferred to WP40c/40d).
- **PubChem + RCSB adapters (WO-10 WP40c):** `PubChemAdapter` (PUG REST: name→CID→properties+PNG, hosts: pubchem.ncbi.nlm.nih.gov) and `RCSBAdapter` (Search API + Data API, hosts: search.rcsb.org, data.rcsb.org, files.rcsb.org, cdn.rcsb.org). Both disabled by default; enable in Settings. Added to ENABLED_ADAPTERS alongside Commons.
- **Figure component + SVG sanitizer (WO-10 WP41):** Added `figure` activity type with `figure_id`, `width`, `height`, `alt` properties. `FigureView` component fetches figure from `/api/figures/:id`, renders SVG inline (sanitized via `sanitizeSvg()` which strips dangerous elements/attributes/URL schemes) or raster as ``. Shows caption, attribution, license. `sanitizeSvg` in `src/ui/lib/svg-sanitizer.ts` uses DOMParser to strip script/object/embed/iframe/form/etc., on* event handlers, and javascript:/data:/vbscript:/file: URL schemes.
- **Import never auto-verifies.** `import_past_paper` forces `verified=false, unverified=true`, derives ids from course + paper + index, and rolls back the whole batch on any citation failure.
- **Verification is explicit.** `update_question` edits content only; only `verify_question` (or the UI action) flips `verified`/`unverified`.
- **Citation validation:** anchors may be explicit `{#id}` or heading slugs; quotes are compared whitespace-normalized inside that section. Banked items require at least one quoted cite.
- **Papers snapshot the bank.** `paper_items` stores question ids at build time; a paper is a stable set even if the bank is edited later.
- **Converter token-limit handling (WO-8 / WP13c):** `tools/convert.py` no longer errors when a section body exceeds `MAX_TOKENS` (1800). `split_section_body` splits oversized section bodies into word-bounded chunks that each fit under the limit, producing multiple notes per section when needed. `split_sections` in `tools/harness/notes.py` now flushes after paragraphs, tables, and lists that push the section token total over the limit. Images and vision-queue entries are preserved across chunks.
- **Papers draw only verified questions.** Selection is restricted to `verified = 1 AND unverified = 0`; a shortfall fails the build instead of padding silently.
- **Scoring is deterministic and server-side.** TF uses `per_statement` by default (or `all_or_nothing`); MCQ can carry negative marks per section; spotter compares normalized text against `answer` plus `accepted`; theory always queues for grading.
- **Active attempt survives reload.** `eh-attempt` stores `{id, course}`; the app routes back to the runner and the timer is derived from the attempt's `started_at`, never from a client-side counter.
- **Spotter images are vault assets.** Paths resolve relative to the first cited note (or from `courses/`); remote/data URLs are rejected and the file must exist inside the vault.
- **Grades are separate from answers.** `answers.auto_score` holds the awarded total for every graded item; `grades` keeps the rubric breakdown, feedback, tags and grader so a re-grade can replace the explanation without losing the score history contract.
- **Theory is never auto-correct.** A graded theory item keeps `correct = null`; the debrief shows the grade and rubric instead of forcing a binary, while evidence uses the 50% threshold only for mastery input.
- **Rubric headings are validated by arithmetic, not by a fixed rubric schema.** A question's rubric is markdown; the grader returns headings with awarded/max, and the server enforces non-empty rows, per-row maxima and the question total. This works with draft rubrics.
- **Evidence is written when an answer becomes final.** Objective answers write evidence at submit; theory writes it at grade time. Re-grading deletes and rewrites that answer's rows, so evidence stays idempotent.
- **SSE is a single local stream.** One EventSource per app shell carries submitted/graded events; the server keeps no per-client state and drops a subscriber when the request aborts.
- **Photo answers live beside the database.** Uploads go to `dirname(db)/uploads` (or `HARNESS_UPLOADS`), not the vault, so student handwriting is not indexed as course material. Only image MIME types with a size cap are accepted, and filenames are attempt/question scoped.
- **The paper list shows the latest attempt.** Results opens the newest submitted attempt for that paper and Resume opens the newest in-progress one; full attempt history is available through the API for later screens.
- **Sessions are first-class, not exam attempts.** `sessions` holds the live teaching loop, `activities` holds each pushed spec/response, and `agent_requests` holds Ask-the-agent messages. Exam attempts stay in `attempts`; the two only meet through evidence.
- **One ActivitySpec catalog.** The server parses every spec with Zod, then checks the semantic rules (cloze blanks, MCQ key, compare-table row width). Unknown component types are rejected before write with the available list, so an agent can self-correct without a round trip through the UI.
- **Every pushed activity is cited.** `validateCites` runs before insert; a bad note, anchor or quote writes nothing. Banking is stricter: at least one cite must carry a quote.
- **Live answers are validated server-side.** The renderer's disabled state and "Still needed" labels are a convenience; `SessionService.respond` rejects a missing MCQ/TF/cloze answer, an out-of-range option, or a too-short think-aloud.
- **Student actions do not forge agent presence.** `agent_seen_at` is touched only by session MCP tools. Reading a session, starting one from the app, answering an activity or banking from the UI never makes the status strip claim an agent is connected. The connected window is 3 minutes so a slow free model does not flicker into "not connected" mid-thought.
- **The long poll is bounded.** `await_response` waits up to 25 s in 400 ms steps, returns one unseen response at a time, and includes open requests and newly seen render errors. Render errors are marked seen so a broken diagram cannot trap the loop forever.
- **The session note is a normal vault note.** Ending writes frontmatter (session id, course, goal, duration, counts) plus the summary and activity log; ending twice returns the existing session rather than overwriting the note.
- **Mermaid is local and lazy.** `mermaid` loads through a dynamic import only when a diagram is present; strict security is on, parse failures are reported to the agent, and the SVG follows the active light/dark theme.
- **Banked activities are vault files for now.** The v1 path stores the spec and citations in `courses/<code>/activities/`; replay, offline scheduling and paper inclusion remain future work after mastery lands.
- **Note editor (N3):** CodeMirror 6 source editor with a side-by-side react-markdown live preview (desktop) / toggle (mobile). Chosen over Milkdown and TipTap because it guarantees round-trip fidelity (frontmatter untouched, `{#anchors}`, wikilinks, tables, mermaid fences and images all preserved byte-for-byte on no-op save), lazy-loads only on the editor screen, works offline with zero network requests, and has reliable mobile typing via the native textarea surface. The toolbar operates on markdown source so "WYSIWYG" means instant preview rather than re-serialization, which keeps the zero-byte-change golden test honest.
- **Goals and plans (M1):** Goals, plan items and tasks are additive SQLite entities. Plans are draft by default and only become approved through an explicit plan-item update; session goal text remains the existing objective field for compatibility.

- **Baseline first (S1):** `bun run typecheck` has 0 errors, `bun test` has 0 failures and 0 errors, `pytest tools` passes without `PYTHONPATH`. CI runs all three.
- **"Where it appears" (S2):** shell status pill (always visible), empty/session screen status text with Start button, Settings agent launcher panel, Agent activity list, inbox per-file status.
- **Launcher config through UI (S3):** argument-array command form, presets for opencode/Kilo, working directory, timeout, runs per hour; loopback-only saves; Test connection reports `await_work`.
- **Server job runner (S4):** leases `executor='server'` jobs in priority order, spawns `tools/convert.py` as argv array, parses JSON progress lines, writes `note_paths_json`, enqueues `vision_transcribe`/`map_concepts` on success, marks `unreadable` on failure.
- **Trigger definitions (S5):** convert (`convert:<sha256>`), map_concepts (`map:<note_path>`, 20/hr), tag_questions (`tag:<question_id>`, 10/hr), write_questions (`write:<course>:<date>`, 5/hr), vision_transcribe (`vision_transcribe:<inbox_item_id>`, 30/hr), find_image (`find_image:<concept_id>`, 10/hr).
- **Launcher security (S6):** config saves and `/api/agent/start` refused unless remote address is loopback; refused entirely when LAN mode is on; never gated on `Origin` header alone.
- **End-to-end loop test (S7):** `tests/loop.test.ts` implements the full upload→sort→convert→map_concepts→fake agent→plan→SSE pill sequence; runs in `bun run verify`.
- **Visible-when-idle rule (S8):** any background job appears in the Agent activity list within one second of creation.
- **Batch sort review screen (WO-11 WP12):** Enhanced `src/ui/screens/Inbox.tsx` to show top-two course suggestions for items needing review. Added `sortInbox` API method calling `/api/inbox/:id/sort`. Each needs_review item shows top suggestion (one-click approve) and second suggestion, plus a reject button. "Approve all top suggestions" button for batch processing.
- **Plan graph strip (WO-11 WP25):** New `src/ui/components/PlanGraphStrip.tsx` component visualizes goal plan items as a horizontal strip in position order, with prerequisite connector lines between items whose concepts have prerequisite edges. Shows status color coding (todo/active/done/deferred/skipped) and partial completion %. Added `concept_id`, `note_path`, `note_anchor` to `PlanItem` type.
